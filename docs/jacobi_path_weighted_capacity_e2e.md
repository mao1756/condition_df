# Path-weighted Jacobi/Rao--Blackwell capacity experiment

## Objective

For one active edge, the model predicts the finite coefficient `q_theta` and the
controller returns

\[
m_\theta=\mu(Y)q_\theta,\qquad \mu(Y)=Y(1-Y).
\]

The new objective is

\[
\mathcal L_{\mathrm{path}}
=\frac{1}{c_{\mathrm{path}}^2}
\operatorname{mean}_{\mu>0}
\frac{(m_\theta-\bar Z)^2}{\max(\mu,10^{-4})},
\]

where the training-only scale is

\[
c_{\mathrm{path}}^2
=\operatorname{mean}_{\mathrm{train},\mu>0}
\frac{\bar Z^2}{\max(\mu,10^{-4})}.
\]

The code never forms the unstable quotient `bar_z / mu`. Exact zero-mobility
lanes are excluded only after checking that their stored Rao--Blackwell target is
exactly zero. Because the weight is a function of the permitted later-state
information, the weighted least-squares population minimizer remains
`E[bar_z | W]`.

## Compared models

- `small-old`: existing 34,974-parameter global-dilated architecture with the
  historical unweighted objective;
- `small-weighted`: the same architecture with the new path-weighted objective;
- `large-weighted`: an eight-block, width-128 circular residual architecture
  with 2,390,174 parameters and the same path-weighted objective.

The sampling comparison also includes a zero-score controller and a
source-informed oracle positive control. All rows in a sampling mode share the
same start state, transition IDs, and reference-noise stream.

## Sampling studies

The first study reverses a fresh endpoint generated by the same K=512 forward
chain. This removes terminal-prior mismatch and is the primary score/capacity
experiment. The second starts from an independent `Dirichlet(1)` state and is a
secondary test of prior mismatch.

Each row saves raw and demixed images at reverse steps 0, 8, 16, 128, 256, 384,
and 512, plus numerical distances, telemetry, contact sheets, selected model
reports, and an automatic interpretation.

## RunPod

See `tools/runpod_weighted_e2e/README.md` for the one-command unattended launch.
The worker has a six-hour process timeout and an independent stop watchdog. Pod
deletion is guarded by an explicit durable-storage declaration and a verified
archive checksum; otherwise the workflow only stops the Pod.
